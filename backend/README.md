# CodeClash — backend

API платформы CodeClash на Rust. Папка — самостоятельный проект: её можно открыть в RustRover отдельно от фронта.

## Стек

actix-web, actix-cors, tokio, serde, sqlx (SQLite), argon2, jsonwebtoken, reqwest

## Запуск

Нужны Rust 1.85+, **Node.js** и **Python 3** — ими запускается код игроков.

```bash
cp .env.example .env
cargo run
```

При первом запуске создастся файл базы `codeclash.db` со стартовыми задачами. Сбросить всё — удалить этот файл.

Проверка: http://127.0.0.1:8000/api/health → `{"status":"ok"}`

Все запросы к API с примерами — в [`requests.http`](requests.http), в RustRover их можно запускать кнопкой ▶.

Тесты (проверка решений, правила победы, бот, рейтинг, генерация задач на поддельной нейросети):

```bash
cargo test
```

|-------------------|----------------------------------|-------------------------------------------------------|
| `HOST`            | `127.0.0.1`                      | Адрес сервера                                         |
| `PORT`            | `8000`                           | Порт сервера                                          |

| `DATABASE_URL`    | `sqlite://codeclash.db?mode=rwc` | Файл базы, создаётся сам                              |
| `JWT_SECRET`      | тестовый                         | Подпись токенов входа. Для деплоя — свой, случайный   |
| `LLM_BASE_URL`    | `https://api.groq.com/openai/v1` | Любой OpenAI-совместимый API                          |
| `LLM_MODEL`       | `qwen/qwen3.8-27b`               | Модель                                                |
| `LLM_API_KEY`     | —                                | Ключ. Пусто — генерация выключена, остальное работает |
| `RUST_LOG`        | —                                | Уровень логов, например `info`                        |

## Нейросеть (Qwen)

Без ключа всё работает на стартовых задачах. Чтобы нейросеть писала новые — бесплатно через [Groq](https://console.groq.com):

1. Зарегистрироваться на [console.groq.com](https://console.groq.com) и создать ключ в API Keys (начинается с `gsk_`).
2. Вписать в `.env`:
   ```
   LLM_BASE_URL=https://api.groq.com/openai/v1
   LLM_MODEL=qwen/qwen3.8-27b
   LLM_API_KEY=gsk_...
   ```
3. Перезапустить `cargo run` — в логе появится «Нейросеть подключена».

У бесплатного Groq лимит ~1000 токенов ответа в минуту. Упёрлись (ответ 429) — сервер сам ждёт, сколько скажет Groq, и повторяет запрос, поэтому генерация иногда идёт до минуты.

Другие варианты — любой OpenAI-совместимый API:
- OpenRouter (платно, копейки): `LLM_BASE_URL=https://openrouter.ai/api/v1`, `LLM_MODEL=qwen/qwen3-coder-30b-a3b-instruct`.
- Локальная Ollama (бесплатно, слабее): `brew install ollama`, `ollama pull qwen2.5-coder:7b`, `LLM_BASE_URL=http://localhost:11434/v1`, `LLM_MODEL=qwen2.5-coder:7b`, ключ не нужен.

### Как генерируется задача

```
1. Нейросеть-автор пишет задачу  → условие, 2 открытых и 4 скрытых теста, эталонное решение (JSON)
2. Сервер проверяет эталон       → не прошёл примеры — задача в мусор (2 попытки);
                                   не прошёл скрытый тест — тест выкидывается (нейросеть ошиблась в ответе)
3. Нейросеть-соперник решает     → видит только условие и примеры, как игрок
4. Сервер проверяет решение бота → сколько тестов оно честно прошло, столько бот и наберёт в матче
5. Задача сохраняется в базу
```

Всё это — заранее, по кнопке «Сгенерировать», а не во время матча: у бесплатных API маленькие лимиты.

## API

Все ошибки приходят в одном формате: `{ "error": "текст" }`. 🔒 — нужен заголовок `Authorization: Bearer <токен>`.

| Метод  | Путь                           | Описание                                                 |
|--------|--------------------------------|----------------------------------------------------------|
| `GET`  | `/api/health`                  | Сервер жив                                               |
| `POST` | `/api/auth/register`           | Регистрация `{ username, password }` → `{ token, user }` |
| `POST` | `/api/auth/login`              | Вход → `{ token, user }`                                 |
| `GET`  | `/api/me` 🔒                   | Кто я + рейтинг и лига по режимам                        |
| `GET`  | `/api/me/matches` 🔒           | История матчей                                           |
| `GET`  | `/api/leaderboard?mode=`       | Топ-20 игроков режима                                    |
| `GET`  | `/api/tasks?mode=&difficulty=` | Список задач                                             |
| `GET`  | `/api/tasks/{id}`              | Задача без скрытых тестов                                |
| `POST` | `/api/tasks/{id}/run`          | Тренировка: только открытые тесты                        |
| `POST` | `/api/tasks/{id}/submit`       | Тренировка: все тесты                                    |
| `GET`  | `/api/llm/status`              | Подключена ли нейросеть                                  |
| `POST` | `/api/tasks/generate` 🔒       | Нейросеть пишет задачу `{ mode, difficulty }`            |
| `POST` | `/api/matches` 🔒              | Начать матч `{ mode, difficulty, bot_level }`            |
| `GET`  | `/api/matches/{id}` 🔒         | Состояние: таймер, прогресс игрока и бота, итог          |
| `POST` | `/api/matches/{id}/run` 🔒     | Открытые тесты, в зачёт не идёт                          |
| `POST` | `/api/matches/{id}/submit` 🔒  | Все тесты — попытка в зачёт → `{ run, match }`           |
| `POST` | `/api/matches/{id}/resign` 🔒  | Сдаться                                                  |
| `POST` | `/api/matches/{id}/review` 🔒  | Разбор кода нейросетью после матча `{ code }`            |
| `GET`  | `/api/tasks/{id}/solution` 🔒  | Тренировка: сдаться и увидеть эталон                     |
| `POST` | `/api/tasks/{id}/review` 🔒    | Тренировка: разбор кода нейросетью `{ code }`            |

### Матч

- **Время:** лёгкая — 5 минут, средняя — 8, сложная — 12. Перед стартом 3 секунды обратного отсчёта.
- **Бот** (`novice` 900 / `middle` 1200 / `senior` 1500): при старте строится расписание его «отправок» — например, 2/4 теста на 90-й секунде, 4/4 на 240-й. Новичок медленнее и в 35% матчей застревает на половине тестов, Сеньор решает в первые минуты. Больше тестов, чем прошло решение нейросети, бот не наберёт. Расписание клиенту не отдаётся.
- **Правила победы** ([`outcome.rs`](src/matches/outcome.rs)): кто первым прошёл все тесты — победил сразу; по таймеру — у кого больше тестов; при равенстве — кто раньше набрал свой результат; никто ничего не отправил — ничья.
- **Итог считается на сервере** при каждом запросе к матчу. Если игрок закрыл вкладку, матч подводится по тем же правилам, когда он откроет профиль или историю.
- **Ответ и разбор:** после конца матча (победа, поражение, «Сдаться», время вышло) `GET /matches/{id}` отдаёт эталон в поле `solution`, а `POST /matches/{id}/review` — разбор кода от нейросети: `{ summary, approach, mistakes, tips }`. Нейросеть получает реальный результат автотестов, чтобы не назвать рабочий код сломанным. Разбор матча сохраняется в базе — повторно лимит не тратится. Пока на задаче идёт твой матч, эталон и разбор на тренировке закрыты.
- **Рейтинг** ([`rating.rs`](src/matches/rating.rs)): Эло против рейтинга бота, свой по каждому режиму. Лиги: Bronze < 1100 ≤ Silver < 1250 ≤ Gold < 1400 ≤ Platinum < 1550 ≤ Diamond.

### Проверка решения

1. Код игрока склеивается с обвязкой ([`harness.js`](src/runner/harness.js) / [`harness.py`](src/runner/harness.py)) и пишется во временную папку.
2. Запускается `node` или `python3`, в stdin уходят **только аргументы** тестов.
3. Обвязка вызывает `solve` на каждом тесте и печатает результаты после маркера `__CODECLASH__`.
4. Сервер сравнивает ответы с ожидаемыми сам — подделать маркер в своём выводе бесполезно.

| `verdict`       | Когда                                        |
|-----------------|----------------------------------------------|
| `accepted`      | Все тесты пройдены                           |
| `wrong_answer`  | Код отработал, но ответ не тот               |
| `runtime_error` | Исключение в тесте или синтаксическая ошибка |
| `time_limit`    | Прогон дольше 5 секунд                       |

> ⚠️ Пока код выполняется прямо на машине с сервером, без изоляции. Для локальной разработки это нормально, но перед тем как сервер увидят другие люди, запуск переедет в Docker-песочницу. Для этого заменится только [`process.rs`](src/runner/process.rs).

## Структура

```
backend/
├── Cargo.toml
├── .env.example
├── requests.http         # готовые запросы для RustRover
├── migrations/           # схема базы, применяется при старте
└── src/
    ├── main.rs           # сборка приложения: база, CORS, роуты
    ├── config.rs         # настройки из .env
    ├── db.rs             # подключение к SQLite, миграции, стартовые задачи
    ├── state.rs          # общее состояние: база, нейросеть, секрет токенов
    ├── error.rs          # AppError → JSON-ответ
    ├── health.rs         # GET /api/health
    ├── auth/             # регистрация, вход, argon2, JWT, AuthUser
    ├── profile/          # /me, таблица лидеров
    ├── tasks/            # задачи: модель, стартовый набор, SQL, обработчики
    ├── runner/           # проверка решений: обвязки, запуск, вердикты
    ├── llm/              # нейросеть: клиент, промпты, генератор задач, разбор решений
    ├── matches/          # матч: бот, правила победы, рейтинг, SQL, обработчики
    └── review/           # правильный ответ и разбор: после матча и «Сдаться» на тренировке
```

Каждая фича — отдельная папка со своей функцией `routes`, которая подключается в `main.rs`.

## Как добавить задачу вручную

Дописать её в [`src/tasks/data.rs`](src/tasks/data.rs), удалить `codeclash.db` (стартовые задачи добавляются в пустую базу) и запустить `cargo test` — тест `every_solution_passes_its_tests` проверит, что эталон проходит все тесты.
