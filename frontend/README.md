# CodeClash — frontend

Клиент платформы CodeClash на Nuxt 4. Что сделано и что дальше — в [общем README](../README.md#задачи-frontend).

## Стек

Nuxt 4, Vue 3 (`<script setup lang="ts">`), TypeScript, Tailwind CSS (`@nuxtjs/tailwindcss`), CodeMirror 6

Редактор — CodeMirror, а не Monaco: собирается локально, без web workers и загрузки с CDN, и легко встраивается в Nuxt.

## Запуск

Нужен Node.js 20+ и запущенный бэкенд (`cd ../backend && cargo run`).

```bash
npm install
npm run dev
```

Открыть http://localhost:3000 — именно `localhost`, а не `127.0.0.1`: бэкенд разрешает запросы (CORS) только с этого адреса.

Проверка типов:

```bash
npx nuxi typecheck
```

## Дизайн

Две темы — светлая с бордовым акцентом (по умолчанию) и тёмная с красным; переключатель в шапке. Выбор хранится в cookie `cc_theme`, поэтому сервер сразу отдаёт страницу в нужной теме, без вспышки. Тема — атрибут `data-theme` на `<html>` ([`useTheme`](app/composables/useTheme.ts), [`app.vue`](app/app.vue)).

Задачи на главной — карточками. Страница задачи и матч — рабочее место во всю высоту экрана: условие слева, редактор и результат справа. Шапка и редактор кода тёмные в обеих темах.

Шрифты (Google Fonts, с кириллицей): **Russo One** — заголовки и логотип, **Jura** — остальной текст. Подключены в [`nuxt.config.ts`](nuxt.config.ts).

Цвета — **дизайн-токены**: CSS-переменные в [`main.css`](app/assets/css/main.css), привязанные к классам в [`tailwind.config.ts`](tailwind.config.ts). В разметке пишем `bg-panel`, `text-muted`, `border-line`, `bg-accent`, `text-easy` — а тёмная тема просто переопределяет переменные под `[data-theme='dark']`. Для редких цветов вне токенов (лиги, медали в рейтинге) — вариант `dark:`.

## Как устроено

- **Адрес API** задан один раз — `runtimeConfig.public.apiBase` в [`nuxt.config.ts`](nuxt.config.ts). Запросы идут через композабл `useApi()`: `apiUrl()` для `useFetch`, `apiFetch()` для кнопок, `authHeaders` — заголовок с токеном.
- **Аккаунт** — композабл `useAuth()`. Токен и пользователь лежат в cookie, поэтому их видит и сервер при SSR, и браузер. Страницы со входом защищает middleware `auth`: без аккаунта отправляет на `/login?redirect=...` и возвращает обратно.
- **Матч** рендерится только в браузере (`ssr: false`). Раз в секунду страница спрашивает сервер о состоянии; таймер считается по часам сервера (`server_now`), чтобы у игрока не было преимущества от сбитых часов. Итог матча решает только сервер.
- **Типы** в `app/types/` повторяют структуры из бэкенда: `Task.ts` ↔ `tasks/model.rs`, `Run.ts` ↔ `runner/model.rs`, `Match.ts` ↔ `matches/model.rs`, `Auth.ts` ↔ `auth` и `profile`.

## Структура

```
app/
  app.vue                    // каркас: шапка + <NuxtPage />
  pages/
    index.vue                // список задач + генерация
    task/[id].vue            // тренировка
    login.vue                // вход и регистрация
    play.vue                 // выбор матча
    match/[id].vue           // матч с ботом
    profile.vue              // рейтинг и история
    leaderboard.vue          // таблица лидеров
  components/
    AppHeader.vue            // навигация, переключатель темы, аккаунт
    TaskCard.vue             // карточка задачи на главной
    PanelTabs.vue            // вкладки над панелью рабочего места
    TaskStatement.vue        // условие и примеры «Ввод / Вывод»
    CodeEditor.client.vue    // редактор CodeMirror
    RunResultPanel.vue       // вердикт, тесты, вывод
    GenerateTaskPanel.vue    // «Сгенерировать задачу»
    SolutionReview.vue       // правильный ответ + разбор кода от нейросети
  composables/
    useApi.ts                // адреса, запросы, заголовок с токеном
    useAuth.ts               // вход, регистрация, выход
    useTheme.ts              // светлая / тёмная тема
  middleware/
    auth.ts                  // страницы только для вошедших
  types/                     // Task, Run, Match, Auth, Review
  utils/
    labels.ts                // подписи и цвета: режимы, сложность, бот, лиги, вердикты
    starterCode.ts           // заготовка кода, формат таймера
    formatStatement.ts       // `код` в условии → <code>
    errorMessage.ts          // текст ошибки из ответа бэкенда
```
